1. Introducción
1.1 Objetivo
Detallar las reglas generales que rigen la operación del Sistema de Quejas, Reclamos, Denuncias y Sugerencias de la Municipalidad, de acuerdo con los casos de uso definidos para registro, administración, seguimiento, notificaciones, reportes, usuarios, permisos, documentos y auditoría.
2. Definición Caso de Uso
2.1 Actores
2.1.1. Ciudadano.
2.1.2. Usuario municipal autorizado.
2.1.3. Administrador del sistema.
2.1.4. Auditor o usuario autorizado.
2.1.5. Sistema.
2.2 Precondiciones
2.2.1. Que el sistema web se encuentre activo y disponible.
2.2.2. Que exista el llamado a una regla de negocio desde uno de los casos de uso.
2.2.3. Que los usuarios internos cuenten con una sesión activa y permisos suficientes cuando la operación lo requiera.
2.3 Flujo Normal Básico
1. El sistema recibe la operación solicitada desde el caso de uso.
2. El sistema identifica las reglas de negocio aplicables.
3. El sistema valida datos, estado del caso, permisos y condiciones de la operación.
4. El sistema permite o rechaza la operación según el resultado de las validaciones.
5. Cuando corresponda, el sistema registra el evento en la bitácora de auditoría.
6. El sistema retorna el resultado al caso de uso invocante.
7. Fin del Caso de Uso.
2.4 Flujos Alternos
FA01: Validación de negocio incumplida. El sistema rechaza la operación, informa la condición que debe corregirse y conserva la información sin cambios.
FA02: Operación no autorizada. El sistema impide la acción cuando el usuario no posee los permisos requeridos.
FA03: Error de procesamiento. El sistema informa que la operación no pudo completarse y evita registrar cambios parciales.
2.5 Poscondiciones
2.5.1. La operación queda ejecutada únicamente cuando cumple las reglas aplicables.
2.5.2. Los eventos sujetos a auditoría quedan registrados con la información requerida.
3. Requerimientos Suplementarios o no Funcionales
ID
Descripción
RNF-01
El sistema debe validar permisos y reglas de negocio antes de ejecutar operaciones protegidas.
RNF-02
Las operaciones auditables deben conservar trazabilidad de usuario, fecha, hora, IP y descripción del evento.
RNF-03
Los registros de bitácora deben ser inmutables desde las funciones normales de la aplicación.
RNF-04
La consulta y generación de reportes no debe modificar la información utilizada como fuente.
RNF-05
Los errores deben informarse sin comprometer la integridad de los datos.
REGLAS DE NEGOCIO
RN01 — Acceso y autenticación
Solo los usuarios activos y con credenciales válidas pueden ingresar a las funciones internas. El sistema debe identificar el rol y los permisos del usuario antes de mostrar las funciones disponibles.
RN02 — Control de permisos
Toda operación protegida debe validarse contra los permisos del usuario. Una operación no autorizada no debe producir cambios.
RN03 — Registro de casos
Todo caso debe clasificarse como queja, reclamo, denuncia o sugerencia. Los datos obligatorios deben estar completos antes de registrar el caso.
RN04 — Identificador de seguimiento
Todo caso registrado correctamente debe recibir un identificador único que permita localizarlo y consultar su seguimiento.
RN05 — Modificación de casos
Solo los usuarios autorizados pueden modificar un caso. El caso debe existir y encontrarse habilitado para modificación. Toda modificación debe conservar trazabilidad.
RN06 — Cierre de casos
Solo un usuario con permiso de cierre puede cerrar un caso. Un caso cerrado debe conservar su información e historial y no debe ser modificado mediante operaciones no autorizadas.
RN07 — Documentos adjuntos
Los documentos solo pueden asociarse a casos existentes y cuando la operación esté permitida. Los archivos deben superar las validaciones configuradas antes de almacenarse.
RN08 — Descarga de documentos
Solo usuarios autorizados pueden descargar documentos asociados a un caso. La descarga debe registrarse en bitácora.
RN09 — Seguimiento
La consulta de seguimiento requiere un identificador o mecanismo autorizado. Solo debe mostrarse la información permitida para el tipo de usuario que consulta.
RN10 — Notificaciones
Las notificaciones deben generarse únicamente para eventos configurados y destinatarios válidos. El resultado del envío debe quedar asociado al seguimiento cuando corresponda.
RN11 — Administración de usuarios
Solo el administrador autorizado puede crear, modificar o cambiar el estado de usuarios. Los datos deben ser válidos antes de guardar cambios.
RN12 — Roles y permisos
Solo el administrador autorizado puede agregar, retirar o modificar roles y permisos. Las configuraciones inválidas deben rechazarse sin alterar la configuración vigente.
RN13 — Reportes
Los reportes deben generarse con criterios válidos y únicamente con información a la que el usuario tenga acceso. Su generación no modifica los datos fuente.
RN14 — Bitácora de auditoría
Deben registrarse como mínimo los inicios y cierres de sesión, creación/modificación/cierre de casos, cambios de usuarios y permisos, y carga/descarga de documentos.
RN15 — Datos mínimos de bitácora
Cada evento auditado debe almacenar usuario, fecha, hora, IP y descripción del evento.
RN16 — Inmutabilidad de bitácoras
Los registros de bitácora no pueden ser modificados ni eliminados desde las funciones de la aplicación.
RN17 — Consulta de auditoría
Solo usuarios con permisos de auditoría pueden consultar bitácoras y generar reportes de auditoría.
