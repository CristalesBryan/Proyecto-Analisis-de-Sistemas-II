1. Introducción.
1.1. Objetivo.
El presente CU tiene como objetivo describir la interacción del ciudadano con el Portal Público del Sistema QRDS de la Municipalidad, permitiendo el acceso sin autenticación a las opciones públicas de registro de quejas, reclamos, denuncias o sugerencias y consulta de seguimiento de casos, así como el acceso al inicio de sesión para usuarios municipales.

2. Definición Caso de Uso
2.1 Actores.
2.1.1. Ciudadano / Usuario Público.
2.1.2. Sistema QRDS.
2.1.3. Usuario Municipal.

2.2 Precondiciones.
2.2.1. Que el sistema web se encuentre activo y disponible.
2.2.2. Que el Portal Público se encuentre publicado y accesible para el ciudadano.
2.2.3. Que los módulos públicos de registro y seguimiento se encuentren disponibles.

2.3 Flujo Normal Básico
1. El ciudadano ingresa al Portal Público del Sistema QRDS.
2. El sistema muestra la página principal sin requerir autenticación.
3. El sistema muestra las opciones principales:
a. Registrar Queja, Reclamo, Denuncia o Sugerencia.
b. Consultar Seguimiento de Caso.
c. Iniciar Sesión para usuarios municipales.
4. El ciudadano selecciona una de las opciones disponibles.
5. El sistema identifica la opción seleccionada.
6. El sistema redirige al caso de uso correspondiente. FA01 FA02 FA03
7. La operación seleccionada se ejecuta de acuerdo con las reglas de negocio del caso de uso invocado.
8. Fin del caso de uso.
2.4 Flujos Alternos.
FA01: Registrar Queja, Reclamo, Denuncia o Sugerencia
1. El ciudadano selecciona la opción “Registrar Queja, Reclamo, Denuncia o Sugerencia”.
2. El sistema redirige al CU-03 Registrar Queja, Reclamo, Denuncia o Sugerencia, sin requerir autenticación para acceder a la opción pública.
3. El registro del caso se realiza conforme a RN03 Registro de casos y RN04 Identificador de seguimiento.
4. Fin del flujo alterno.
FA02: Consultar Seguimiento de Caso
1. El ciudadano selecciona la opción “Consultar Seguimiento de Caso”.
2. El sistema redirige al CU-05 Consultar Seguimiento de Caso.
3. El ciudadano proporciona el identificador o mecanismo de consulta requerido.
4. El sistema valida que el caso exista y muestra únicamente la información permitida para la consulta pública, de acuerdo con RN09 Seguimiento y RN05 del documento de Reglas de Negocio para Casos de Uso.
5. Si el caso no existe o el mecanismo de consulta no es válido, el sistema informa la situación y permite realizar una nueva consulta.
6. Fin del flujo alterno.
FA03: Iniciar Sesión
1. El usuario municipal selecciona la opción “Iniciar Sesión”. El sistema redirige al CU-01 Iniciar Sesión, donde se aplican las reglas de acceso y autenticación correspondientes.
2.5 Postcondiciones.
2.5.1. El ciudadano o usuario municipal fue redirigido al módulo seleccionado.
2.5.2. El Portal Público no modifica información del caso por sí mismo; cualquier registro, consulta o autenticación se procesa en el caso de uso correspondiente.
2.5.3. Los eventos sujetos a auditoría se registran únicamente cuando lo establece el TDR y las reglas de negocio aplicables, incluyendo inicios y cierres de sesión, creación, modificación y cierre de casos, cambios de usuarios y permisos, y carga o descarga de documentos.
3. Requerimientos Suplementarios o no Funcionales
3.1. El Portal Público debe operar de forma segura y estar disponible para los ciudadanos. Las operaciones protegidas deben validar permisos antes de ejecutarse.
