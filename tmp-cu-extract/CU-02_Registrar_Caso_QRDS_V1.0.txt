2. Introducción
El presente caso de uso CU-02 describe el proceso mediante el cual un ciudadano registra un caso en el Sistema QRDS. Este módulo es de acceso público y no requiere autenticación previa, garantizando que cualquier ciudadano pueda ejercer su derecho de presentar quejas, reclamos, denuncias o sugerencias ante la institución.
El sistema genera automáticamente un código de seguimiento único que permite al ciudadano rastrear el estado de su caso sin necesidad de crear una cuenta. Todo el proceso queda registrado en la bitácora de auditoría.

3. Objetivo
Permitir a cualquier ciudadano registrar un caso (queja, reclamo, denuncia o sugerencia) de forma pública, segura y trazable, generando automáticamente un código de seguimiento único, notificando al ciudadano por correo electrónico y dejando constancia inmutable en la bitácora de auditoría del sistema.

5. Actores
ID
Actor
Descripción
AC-01
Ciudadano
Usuario público (anónimo) que accede al formulario de registro desde el portal CU-00. No requiere autenticación.
AC-02
Sistema QRDS
Valida los datos, genera el código de seguimiento, almacena el caso en BD, envía confirmación y registra en bitácora.
AC-03
Servidor de Correo
Servicio SMTP que envía la confirmación de registro con el código de seguimiento al ciudadano.
AC-04
Módulo de Bitácora
Registra de forma inmutable la creación del caso: usuario (anónimo/IP), fecha, hora, tipo de caso y código generado.

6. Precondiciones
El portal público (CU-00) debe estar activo como punto de acceso.
El backend (Spring Boot) debe estar disponible para recibir el registro.
La base de datos debe estar operativa con la tabla 'casos' lista para inserción.
El servidor de archivos debe estar disponible si se adjuntarán documentos.
El servidor de correo (SMTP) debe estar configurado para envío de confirmaciones.
El módulo de bitácoras debe estar activo para registrar el evento de creación.
La tabla de áreas/dependencias debe estar poblada con las opciones configuradas por el administrador.

8. Flujos Alternos
Código
Nombre
Descripción
FA-01
Tipo de Caso — Denuncia
Si el ciudadano selecciona 'Denuncia', el formulario muestra campos adicionales: nombre del funcionario/área denunciada (opcional) y opción de presentar la denuncia de forma anónima. [RN-09]
FA-02
Adjuntar Documentos
El ciudadano adjunta uno o más archivos de soporte. El sistema valida: tipo de archivo (PDF, JPG, PNG, DOCX), tamaño máximo por archivo (5 MB) y máximo 5 archivos por caso. Si alguno no cumple, muestra mensaje de error específico por archivo. [RN-03]
FA-03
Campos Obligatorios Incompletos
El ciudadano intenta enviar el formulario con campos obligatorios vacíos o con formato inválido. El sistema resalta los campos en rojo con mensaje descriptivo por campo. El botón 'Enviar Caso' permanece activo pero muestra los errores al presionarlo. Regresa al paso 5.
FA-04
Correo de Confirmación Fallido
El servidor SMTP no puede enviar el correo de confirmación. El caso ya fue registrado exitosamente en BD (paso 11). El sistema muestra el código de seguimiento en pantalla con aviso: 'No fue posible enviar la confirmación por correo. Su código de caso es: [CÓDIGO]. Guárdelo para dar seguimiento.' Registra el fallo de notificación en el log del sistema.
FA-05
Error de Conexión al Enviar
El backend no responde al intentar guardar el caso. El sistema muestra: 'Error al registrar su caso. Verifique su conexión e intente nuevamente.' El formulario conserva los datos ingresados para no obligar al ciudadano a escribir de nuevo.
FA-06
Caso Duplicado Detectado
El sistema detecta que el mismo correo electrónico ya tiene un caso activo con descripción muy similar en las últimas 24 horas. Muestra aviso: 'Detectamos que puede tener un caso similar registrado recientemente. Código: [CÓDIGO]. ¿Desea continuar con un nuevo registro?' El ciudadano decide si continúa o consulta su caso existente.

9. Postcondiciones
El caso queda almacenado en la BD con estado RECIBIDO y código de seguimiento único.
El ciudadano recibió (o visualizó en pantalla) el código de seguimiento.
El ciudadano recibió confirmación por correo electrónico (si proporcionó email y no es anónimo).
El evento de creación del caso quedó registrado en la bitácora de auditoría de forma inmutable.
Los documentos adjuntos (si los hubo) quedaron almacenados y referenciados en BD.
El caso está disponible para ser asignado a un agente (CU-03: Gestionar Caso).

11. Reglas de Negocio
Código
Descripción
RN-01
El registro de casos es de acceso público. No se requiere autenticación. Cualquier ciudadano puede registrar un caso desde el portal sin crear una cuenta.
RN-02
Los cuatro tipos de caso (Queja, Reclamo, Denuncia, Sugerencia) son mutuamente excluyentes. El ciudadano debe seleccionar exactamente uno por registro.
RN-03
Los archivos adjuntos deben cumplir: formatos permitidos (PDF, JPG, JPEG, PNG, DOCX), tamaño máximo de 5 MB por archivo, máximo 5 archivos por caso. Los archivos se almacenan en el servidor de archivos y se referencia su ruta en la BD.
RN-04
El ciudadano debe aceptar el aviso de privacidad antes de enviar el caso. Este aviso debe informar cómo se tratarán sus datos personales conforme a la legislación vigente.
RN-05
Campos obligatorios del formulario: tipo de caso, nombre completo del ciudadano, correo electrónico (formato válido), área/dependencia relacionada, descripción del caso (mínimo 50 caracteres, máximo 2000 caracteres).
RN-06
El código de seguimiento se genera automáticamente con el formato: [TIPO]-[AÑO]-[CORRELATIVO 5 DÍGITOS]. Ejemplos: Q-2026-00001, D-2026-00023, S-2026-00150. El correlativo es secuencial por tipo de caso y año. Este código es único e irrepetible.
RN-07
El sistema envía automáticamente un correo de confirmación al ciudadano con: código de seguimiento, tipo de caso registrado, fecha de registro, plazo estimado de respuesta según tipo (Queja: 15 días hábiles, Reclamo: 20 días hábiles, Denuncia: 30 días hábiles, Sugerencia: 30 días hábiles) y URL para consultar el estado.
RN-08
Todo registro de caso debe quedar en la bitácora de auditoría con: IP del ciudadano, fecha, hora, tipo de caso, código generado, correo del ciudadano (si no es anónimo). La bitácora es INMUTABLE.
RN-09
Las denuncias pueden presentarse de forma anónima. En ese caso, el campo 'nombre completo' y 'correo electrónico' son opcionales. Si la denuncia es anónima, no se puede enviar confirmación por correo y el código de seguimiento debe mostrarse en pantalla con instrucción de guardarlo.
RN-10
El estado inicial de todo caso recién registrado es: RECIBIDO. Este estado indica que el caso fue recibido y está pendiente de asignación a un agente.

12. Requerimientos No Funcionales
ID
Tipo
Descripción
RNF-01
Rendimiento
El formulario debe cargar en ≤ 2 segundos. El proceso de registro (validación + guardado + correo) debe completarse en ≤ 5 segundos.
RNF-02
Seguridad
Implementar CAPTCHA o reCAPTCHA para prevenir registros automatizados (bots). Rate limiting: máx. 5 registros por IP en 10 minutos.
RNF-03
Usabilidad
Formulario multi-paso (wizard) de 3 pasos: 1) Tipo de caso, 2) Datos del ciudadano + descripción, 3) Adjuntos + confirmación. Indicador de progreso visible.
RNF-04
Disponibilidad
El módulo de registro debe estar disponible 24/7, independientemente del estado de otros módulos del sistema.
RNF-05
Accesibilidad
Cumplir WCAG 2.1 nivel AA. Formulario navegable por teclado. Labels accesibles en todos los campos.
RNF-06
Integridad
Una vez registrado, el caso no puede ser eliminado por el ciudadano. Solo los administradores pueden marcar un caso como 'Anulado' con justificación, lo cual queda en bitácora.
