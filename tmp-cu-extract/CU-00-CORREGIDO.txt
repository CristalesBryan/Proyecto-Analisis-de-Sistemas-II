Introducción.
Objetivo.
El presente CU tiene como objetivo describir la interacción del ciudadano con el Portal Público del Sistema QRDS, permitiendo el acceso sin autenticación al contenido informativo, al registro de casos y a la consulta pública por código de seguimiento, así como el acceso al inicio de sesión para usuarios internos.

Definición Caso de Uso
2.1Actores.
2.1.1. Ciudadano / Usuario Público RN01
2.1.2. Sistema QRDS.
2.1.3. Servidor Web.
2.1.4. Administrador del Sistema.


2.2Precondiciones.
2.2.1. Que el servidor web y el backend Spring Boot se encuentren activos.
2.2.2. Que la base de datos PostgreSQL se encuentre operativa.
2.2.3. Que el portal se encuentre publicado mediante HTTPS.
Flujo Normal Básico
El ciudadano ingresa a la URL del Portal Público del Sistema QRDS.
El sistema carga la página principal y muestra el contenido institucional sin requerir autenticación. RN01
El sistema muestra las opciones principales:
Registrar Queja, Reclamo, Denuncia o Sugerencia.
Consultar Estado de Mi Caso.
Iniciar Sesión para funcionarios.
El sistema registra el acceso público en la bitácora correspondiente. RN14
El ciudadano selecciona una de las opciones disponibles.
El sistema redirige al caso de uso correspondiente. FA01 FA02 FA03
Fin del caso de uso.
FA03: Iniciar Sesión
1. El ciudadano o funcionario selecciona “Iniciar Sesión”. El sistema redirige a CU-01.
Flujos Alternos.
FA01: Registrar Caso
El ciudadano selecciona la opción “Registrar Queja”.
El sistema redirige al formulario público CU-02 sin requerir autenticación. RN01
Fin del flujo alterno.
FA04: Código inválido o no encontrado
FA02: Consultar Estado de Caso
El ciudadano selecciona la opción “Consultar Estado de Mi Caso”.
El sistema redirige a CU-07. El ciudadano ingresa un código con formato [TIPO]-[AÑO]-[CORRELATIVO 5 DÍGITOS], por ejemplo Q-2026-00001. RN03
El sistema muestra únicamente la vista pública permitida: código, tipo, estado, fechas, avance, seguimientos públicos y resumen de resolución cuando corresponda. RN11
Si el formato no cumple ^[QRDS]-\d{4}-\d{5}$, el sistema informa el formato válido. Si el código no existe, muestra “Código no encontrado. Verifique el número e intente nuevamente”.
Postcondiciones.
El ciudadano accedió al módulo seleccionado. Los accesos y eventos relevantes quedaron registrados en bitácora inmutable. Si se realizó una consulta pública, no se expusieron datos personales, observaciones internas, agente, IP, bitácora interna ni adjuntos. RN11 RN14
